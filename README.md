# JUUNIBI

Монорепозиторий (npm workspaces, TypeScript strict).

- `packages/core` — ядро без зависимостей: `Kernel` (плагины, порядок по зависимостям, изоляция сбоев, остановка в обратном порядке), типизированный `EventBus`, иммутабельный `Store` с селекторами, `Result`, `Logger`.
- `apps/web` — веб-версия на Vite: тёмная/светлая тема, a11y, адаптивность, сохранение в localStorage.

```
npm install
npm run dev        # веб в режиме разработки
npm test           # тесты ядра
npm run typecheck
npm run build
```

## Запуск одним файлом (Windows)

`JUUNIBI.bat` — работает с любого носителя (флешка, сетевая папка, обычная папка). Если Node.js 20+ нет, скачает переносную версию (с проверкой SHA-256) в `.runtime`, затем: установит зависимости → проверит типы → прогонит тесты → соберёт → найдёт свободный порт (с 4173) → запустит сервер → откроет браузер.
Параметры: `--dev`, `--no-open`, `--skip-checks`, `--port N`. На других ОС: `npm start`.

## Python-лаунчер

`python juunibi.py [--dev] [--no-open] [--skip-checks] [--port N]` — то же самое на Windows/macOS/Linux (Python 3.9+, только стандартная библиотека). Если Node.js 20+ нет, скачивает его в `.runtime` с проверкой SHA-256, дальше запускает `scripts/launch.mjs`.

## Личный помощник

Пакет `packages/assistant` + сервер `apps/server` + чат в `apps/web`.

- **Модель:** Cloud.ru Foundation Models (OpenAI-совместимый API). Скопируйте `.env.example` в `.env`, впишите `CLOUDRU_API_KEY` и `CLOUDRU_MODEL`. Ключ живёт только на сервере (`.env` и `data/` в git не попадают).
- **Знает проект:** видит список модулей ядра (`kernel.describe()`). Любой модуль даёт ему инструменты: `deps: ["assistant"]` + `ctx.service("assistant:tools").register({...})`.
- **Контроль:** инструменты с риском `write`/`danger` выполняются только после одобрения хуком `approve` (супервайзер); по умолчанию — отказ.
- **Обучение:** 👍/👎 в чате меняют вес воспоминаний; после оценки помощник предлагает «уроки», которые попадают в память только после вашего «Принять». Оценённые 👍 диалоги экспортируются в JSONL (`GET /api/dataset`) для дообучения на Cloud.ru. Само дообучение весов автоматически не запускается.

## Помощница: память, инструменты и качество

Всё ниже настраивается в «Настройках → Поведение помощницы» и хранится на вашем компьютере (`data/`). Настройки только ограничивают или настраивают помощницу: записи в память по-прежнему требуют вашего «Принять», действия с последствиями — подтверждения.

- **Память** (плитка на странице «Мозг»): закрепление важного, срок жизни записи (после него запись уходит в «Архив» и не попадает в ответы), экспорт и импорт файлом (импорт всегда создаёт *предложения*, ничего не включая сам), расширенные автопредложения «запомнить» (выкл / по фразам / умно).
- **Поиск по смыслу.** По умолчанию включён с моделью `BAAI/bge-m3` (меняется в настройках или `CLOUDRU_EMBEDDING_MODEL`). После 3 сбоев подряд на 10 минут отключается сам, поиск идёт по словам. Кнопка «Проверить» показывает, работает ли модель у вас.
- **Сводка длинных бесед.** То, что не помещается в окно из последних 20 сообщений, сжимается в краткое содержание (отдельный вызов модели после ответа).
- **Инструкции** («Настройки → Инструкции»): что помощнице знать о вас и как отвечать, до 1500 символов в каждом поле. Уходят с каждым запросом, поэтому повторять их в чатах не нужно; действий не разрешают.
- **Интернет** («Настройки → Инструменты → Доступ в интернет», по умолчанию выключен): поиск (`web_search`) через DuckDuckGo без ключа или Brave Search со своим ключом, чтение страницы (`web_open`, до 8000 символов текста) и русская Википедия (`wiki_search`, `wiki_read`). Только чтение. Открываются лишь ссылки из результатов поиска и из ваших сообщений, поэтому текст на чужой странице не может заставить помощницу отправить данные по своему адресу. Адреса этого компьютера и домашней сети закрыты (проверяется каждый ответ DNS и каждое перенаправление), размер ответа ограничен 2 МБ, время 15 секундами. Ключ Brave хранится в `data/assistant-settings.json` и в браузер не отдаётся.
- **Дела** (пункт «Дела» в меню): дела с галочками, заметки и напоминания на одной странице, поиск и фильтры, правка текста и времени на месте. Напоминания бывают разовыми и повторяющимися: каждый день, по будням или каждую неделю. Повторяющееся срабатывает отдельной копией и переходит на следующий раз; если JUUNIBI был закрыт несколько дней, пропущенное срабатывает один раз. Помощница ставит повторяющиеся напоминания из чата: «напоминай по будням в 10:00 про стендап».
- **Инструменты.** Заметки и дела, напоминания (срабатывают, пока JUUNIBI запущен; уведомление в браузере по желанию), сводка дня (`/сводка`), чтение и поиск в **одной выбранной вами папке** (секреты, `.git`, `node_modules` и ссылки наружу закрыты), справочник (русская Википедия, со ссылкой на источник). Запись текстовых документов в ту же папку включается отдельным переключателем, всегда требует подтверждения и сохраняет прежнюю версию в `data/file-backups`.
- **Быстрые команды** (`/имя`): создаются в настройках или по подсказке на главной, если вы трижды просили одно и то же.
- **Качество** (плитка «Качество»): отчёт по 👍/👎, где помощница ошибается чаще, набор для дообучения с замаскированными ключами и контактами (само дообучение не запускается) и 12 **контрольных вопросов** с историей запусков — запускайте после смены модели или инструкций; они не оставляют следов в чатах и памяти и не выполняют действий.

Файлы данных: `assistant-settings.json`, `organizer.json`, `summaries.json`, `evals.json`, `file-backups/`.

Не поддерживается намеренно: вложения PDF, таблиц Excel и изображений (нужны отдельные библиотеки и модель с изображениями; CSV, JSON и текст работают), отправка писем и исполняемые плагины.

## Обновление: безопасность, откат и установка в один клик

- **Только проверенные версии.** Скачивается лишь коммит, у которого на GitHub прошли все автоматические проверки (CI). Если проверки ещё идут, не пройдены или результата нет, кнопка «Скачать» заблокирована с объяснением. Для форка без CI: `JUUNIBI_UPDATE_REQUIRE_CI=0` в `.env`.
- **Скачиваются только изменённые файлы.** Совпадающие с диском файлы берутся с диска; прерванная загрузка той же версии продолжается с уже проверенных файлов; при сбоях сети и ошибках сервера (5xx, 429) файл повторно запрашивается до 3 раз; загрузку можно отменить.
- **Код из обновления не получает лишнего.** `npm ci` во временной папке запускается с `--ignore-scripts` (скрипты зависимостей не выполняются), а переменные окружения с ключами и токенами проверкам не передаются.
- **Установка сразу.** Кнопка «Установить сейчас» перезапускает JUUNIBI через лаунчер (код выхода 75), страница обновляется сама. Если в этот момент идёт ответ помощницы, ждут решения действия или выполняются планы Мозга, перед перезапуском показывается предупреждение. Без лаунчера (`node apps/server/dist/server.mjs`) кнопка честно сообщает, что перезапуск нужно сделать вручную.
- **Автоматический откат.** Если новая версия не прошла проверки, не собралась или не отвечает после запуска, лаунчер возвращает прежние файлы и запускает прежнюю версию (`startup_failed` в истории). Установка считается окончательной только после ответа сервера.
- **Ручной откат и история.** Страница «Обновление» показывает историю (`.updates/history.jsonl`) и кнопку «Откатить на предыдущую версию»; откат выполняется при следующем запуске или кнопкой «Откатить сейчас». Откатываются установки по порядку, от последней. Хранятся 3 последние резервные копии.
- **Установка не трогает лишнее.** Файлы, совпадающие с новой версией, не перезаписываются и не копируются в резервную копию; после установки папка `staging` удаляется; зависимости переустанавливаются, только если изменился `package-lock.json`.
- **Что нового, каналы, автопроверка.** Список изменений между вашей и новой версией (с номерами PR), выбор канала («Свежий» — каждая проверенная версия, «Стабильный» — только выпуски GitHub) и частота автопроверки (каждый час / раз в сутки / выключена) — в блоке «Настройки обновления». Понятное сообщение при лимите запросов GitHub; для повышенного лимита задайте `GITHUB_TOKEN` в `.env`.
- **Итог проверок.** Страница показывает, какие из шагов (зависимости, типы, тесты, сборка) прошли, а при ошибке — последние строки вывода.

## Обновление: проверка запуска и удаление файлов

- После установки инсталлятор делает **проверку запуска** (`health_check_started/done`): каждый установленный файл сверяется с манифестом, скрипты `scripts/*.mjs` проверяются на синтаксис, `package.json` — на валидность. Если проверка не пройдена — автоматический откат и `update_failed`.
- Файлы, которые убрала новая версия, **не удаляются сами**. Они показываются красным и удаляются только после кнопки «Подтвердить удаление» для именно этого обновления (с резервной копией и откатом). Предлагаются к удалению только файлы, установленные предыдущим обновлением (`.updates/installed.json`), поэтому ваши собственные файлы не затрагиваются.
- Новые события: `file_download_progress` (для файлов больше 256 КБ), `file_install_failed`, `file_remove_done`, `removals_confirmed`.
- Ограничения: подтверждать удаление нужно до перезапуска; сбой записи отдельного файла отдельным тестом не покрыт.

## Интерфейс

- **Левое меню:** Главная, Дела, Модули, Мозг, Обновление, Настройки. На телефоне открывается кнопкой ☰.
- **Аватар:** круглая кнопка поверх всего сайта. Перетащите её куда угодно (положение запоминается; стрелки — для клавиатуры), нажмите — откроется чат. `Ctrl+K` открывает и закрывает чат.
- **Свой образ:** положите картинку в `apps/web/public/avatar.webp` (подойдут и `.png`/`.jpg` после правки пути в `avatar.ts`) — пока файла нет, показывается буква «J». Логотип в меню: слот `.brand` в `apps/web/src/main.ts`.
- **Чат в стиле ChatGPT:** список чатов слева (поиск, переименование, удаление, группы по датам), потоковый вывод ответа, Markdown (списки, таблицы, блоки кода с «Копировать»), остановка генерации, «Сгенерировать заново», изменение своего сообщения, 👍/👎, копирование, кнопка «вниз». История чатов хранится в браузере; сервер получает её с каждым запросом.
- **Шаги и память на виду:** живые карточки «Смотрю модули проекта…» (с итогом и временем), пометка «Использована память · N» со списком записей, кнопка «Запомнить это» у ваших сообщений, запрос разрешений — прямо в ленте.
- **Команды и быстрые действия:** `/` открывает меню — `/новый`, `/запомни <текст>`, `/память`, `/модули`, `/обновления`, `/настройки`, `/экспорт` (Markdown), `/очистить`, `/сцены`, `/помощь`. Черновик сохраняется отдельно для каждого чата; `↑` в пустом поле — править последнее сообщение; `Enter` — отправить, `Shift+Enter` — новая строка; `Ctrl+K` — открыть/закрыть чат, `Ctrl+Shift+O` — новый чат, `Ctrl+/` — справка, `Esc` — закрыть меню, затем чат.
- **Файлы и голос:** до 5 текстовых файлов/кода (до 100 КБ каждый, до 250 КБ всего) — скрепкой, перетаскиванием или вставкой; файл уходит модели как блок кода, в ленте виден как чип. Диктовка (микрофон) и озвучка ответов — средствами браузера; **в Chrome/Edge распознавание речи выполняют серверы Google/Microsoft**, озвучка идёт локально.
- **Окно:** перетаскивается за шапку, меняет размер за края и углы, запоминает место; двойной клик по шапке — на весь экран; меню «Вид» — плотность (свободно/компактно) и размер текста. На телефоне — всегда на весь экран.
- **Чего нет по сравнению с ChatGPT:** картинок и PDF (модель текстовая).

## Оформление чата

Тёмная и светлая темы с тёплым золотым акцентом: «свечение» в углу окна, стеклянная шапка со статусом («на связи · модель»), подвал сайдбара со статусом помощницы, пузыри с мягкой тенью, аватар у каждого ответа, приветствие по времени суток и карточки-подсказки с иконками, поле ввода с подсветкой фокуса и золотой кнопкой отправки, подсветка синтаксиса в блоках кода (JS/TS, Python, Bash, SQL, JSON, YAML, CSS, HTML, Go/Rust/Java/C-подобные), анимации появления (отключаются при «уменьшить анимацию»). Образ помощницы — файл `apps/web/public/avatar.webp` (без него показывается буква «J»).

### Живые детали чата

- **Потоковый текст без перерисовки:** уже показанные абзацы не пересоздаются — выделение мышью и прокрутка не сбиваются, пока ответ дописывается; новые блоки плавно появляются.
- **Статус в шапке:** «на связи · модель» → «печатает ···» / название текущего шага; аватар мягко пульсирует, «искры» на фоне оживают.
- **Длинный код** (больше 22 строк) сворачивается с плавным затуханием и кнопкой «Показать ещё N строк».
- **Сайдбар:** у каждого чата превью последнего сообщения и время («5 мин», «вчера», «12 окт»); внутри чата — разделители дней.
- **Акцентный цвет:** Золото, Сакура, Нефрит, Фиалка (меню «Вид» в чате); контраст всех вариантов в светлой и тёмной темах проверяется тестами.

## Страница «Обновление»

Одна колонка вместо трёх столбцов:

1. **Карточка состояния** — крупный статус («Доступна новая версия», «Скачиваем обновление», «Готово к установке», «Не удалось подготовить…»), версии «Установлена → Новая», описание коммита, главная кнопка по ситуации; во время работы — реальный прогресс (файлы и байты) и компактная «лента передачи» GitHub → Проверка → Ваш проект, по которой летит файл при каждом настоящем событии.
2. **Этапы:** проверка версии → загрузка → проверка целостности → тесты и сборка → готово к установке → установка (при запуске лаунчера). Ошибка отмечается на том этапе, где случилась.
3. **Результат установки:** карточка «Обновление установлено» (проверка запуска, папка резервной копии) или «Установка не удалась — выполнен откат» с причиной; подтверждение удаления файлов.
4. **Что изменится:** фильтры (все изменения / новые / изменённые / удалённые / без изменений), файлы по папкам со статусом каждого; папки с тысячами файлов строятся лениво. Файл с ошибкой виден при любом фильтре.
5. **Журнал событий** — сворачиваемый.

Ничего не придумывается: все числа и статусы берутся из состояния сервера и журнала событий (`buildUpdateModel`, покрыт тестами).

## Страницы приложения

- **Главная:** приветствие с аватаром и главными действиями; блок «Требует внимания» (нет ключа, ждут решения действия, доступно/скачано обновление, записи памяти на подтверждение, сбой модуля) или спокойное «Всё в порядке»; карточки Версия / Память / Модули со статусами; «Недавние чаты» — клик открывает именно этот разговор.
- **Память:** работает и без ключа Cloud.ru. Добавление вручную (факт/предпочтение), поиск, фильтры (все / ждут решения / факты / предпочтения / уроки), блок «Ждут вашего решения» с «Принять все», карточки с типом, возрастом и «полезностью», удаление с подтверждением.
- **Модули:** реальные компоненты сервера (память, помощница, подтверждение действий, сцены, обновление) с живым статусом и пояснением; зависимости видны отступом и подписью «зависит от»; помощница получает тот же список.
- **Мобильное приложение:** JUUNIBI на телефоне через домашний Wi-Fi (отдельный модуль `mobile`). Доступ выключен по умолчанию; когда он включён, второй сервер слушает порт 4180 (`JUUNIBI_LAN_PORT`), а основной по-прежнему только на 127.0.0.1. Телефон подключается по QR-коду или одноразовому коду из 8 цифр и получает свой ключ устройства; без него в сети не открывается ничего, кроме страницы ввода кода. Управлять доступом и устройствами можно только с компьютера. Страницу можно добавить на главный экран телефона как приложение.
- **Настройки:** подключение Cloud.ru (статус, показать/скрыть ключ), тема карточками-превью, акцентный цвет, плотность и размер текста чата, сцены персонажа, данные (размер истории, экспорт, удаление), о программе.


## Мозг JUUNIBI (Brain Core, первый этап)

В меню добавлен раздел **Мозг**. Серверный `BrainCore` (`apps/server/src/brain.ts`) предоставляет режимы `chat`, `analysis`, `agent`, `creative`, создание ограниченных планов и контроль статусов шагов. На странице можно сменить режим и создать план. Данные доступны по `GET /api/brain`, `POST /api/brain/mode`, `POST /api/brain/plans`, `POST /api/brain/execute-read`, `GET /api/brain/history`.

**Границы версии:** планировщик пока не вызывает модель и не выполняет шаги автоматически; выбор режима пока не меняет поведение чата. Планы находятся в оперативной памяти процесса и исчезают при перезапуске. Реальные инструменты и запись файлов продолжат требовать существующих разрешений. Далее: постоянное хранилище, интеграция с Assistant, исполнение только через ApprovalGate и журнал операций.

На следующем этапе добавлено реальное выполнение только разрешённых операций чтения (`list_modules`, `search_memory`), а также журнал результатов. API не позволяет вручную отметить шаг выполненным без результата инструмента. Запись и опасные действия по-прежнему проходят через `ApprovalGate` помощницы, а не через этот исполнитель.


### Brain Core: сохранение и последовательные шаги

Планы, режим мозга и журнал сохраняются в `data/brain.json` (существующий атомарный файл-хранилище). При запуске состояние восстанавливается; прерванные активные шаги переводятся в ожидание. API `POST /api/brain/execute-sequence` принимает идентификатор плана и массив разрешённых действий (`list_modules`, `search_memory`) в порядке шагов. При первой ошибке выполнение прекращается; остальные шаги не запускаются. Сторонние инструменты, запуск команд и запись файлов этот маршрут не поддерживает. Левое меню не расширено.


### Автоматический мозг — упрощённый интерфейс

Раздел «Мозг» теперь показывает только состояние и планы — без кнопок выбора режима и ручной формы. В чате доступен инструмент `brain_run_safe_plan`: с подтверждения пользователя он создаёт план и последовательно выполняет `list_modules`/`search_memory`, останавливаясь при ошибке. Произвольные команды, изменения файлов и публикации этим инструментом не выполняются. Режимы остаются доступны через API для совместимости.


### Улучшенная память v2

Память нормализует регистр, ё/е, Unicode и пробелы при поиске дубликатов; предложения остаются неподтверждёнными до решения пользователя. Поиск учитывает уникальные совпадающие слова и ограничивает выдачу, не раскрывая изменяемые внутренние объекты. При загрузке проверяется формат записей, а ошибки сохранения больше не скрываются. Интерфейс «Мозг» и боковое меню не меняются.


### Memory 3.0 — связи и актуальность

Внутренний поиск памяти теперь корректно разбивает Unicode-слова и учитывает небольшой словарь близких понятий (это лексический поиск, не векторные embeddings). Добавлены серверные методы `relate`, `setExpiry`, `supersede`: связи между подтверждёнными фактами, явный срок действия и замена устаревших сведений без потери истории. Истёкшие и заменённые факты исключаются из контекста ИИ. Автоматически объявлять сведения ложными по возрасту система не будет. UI/меню «Мозг» не меняются.


### Memory 3.1

Поддерживается опциональный `EmbeddingProvider` для гибридного поиска с автоматическим возвратом к локальному поиску при сбое. `context` ограничивает размер извлекаемых воспоминаний. Инструмент `propose_memory_revision` создаёт неподтверждённое предложение исправить факт; замена происходит только после одобрения. Векторный провайдер ещё требует отдельной настройки и совместимого API. Кнопки и меню не меняются.


### Memory 3.1 — подключение эмбеддингов Cloud.ru

Смысловой поиск можно включить без изменения интерфейса, задав в `.env` переменные `CLOUDRU_EMBEDDING_MODEL=BAAI/bge-m3` и `CLOUDRU_API_KEY`. При необходимости используется `CLOUDRU_EMBEDDING_BASE_URL` (по умолчанию `https://foundation-models.api.cloud.ru/v1`). Если API недоступен, Memory автоматически возвращается к лексическому поиску. Ключ не выводится в журналы. Наличие модели в каталоге Cloud.ru не гарантирует доступ к endpoint на конкретном аккаунте; перед эксплуатацией проверьте успешный запрос `/v1/embeddings`. Настройки интерфейса не меняются.


### Cloud.ru: общий ключ, разные модели

После настройки Cloud.ru в JUUNIBI память автоматически получает тот же API-ключ, что и чат, включая ключ из сохранённого файла настроек. Повторный ввод ключа и переменная `CLOUDRU_API_KEY` не нужны. Для векторизации по умолчанию запрашивается `BAAI/bge-m3`; можно переопределить модель через `CLOUDRU_EMBEDDING_MODEL`. Чат-модель и embedding-модель отличаются. Если сервис векторизации недоступен, поиск возвращается к локальному алгоритму. Без нового UI проверить использование можно через `GET /api/memory/diagnostics` (счётчики запросов и ошибок, без секретов).


### Автоматические предложения памяти (без новых элементов интерфейса)

После ответа JUUNIBI локально распознаёт явные фразы пользователя «Запомни…», «Я предпочитаю…» и «Мне нравится, когда…». Новые факты попадают только в `pending`, пока пользователь не подтвердит их в существующем разделе памяти. ИИ не использует неподтверждённые предложения; дубли устраняются, строки с возможными секретами и цитаты отбрасываются. Неявные выводы о пользователе автоматически не сохраняются. Чат продолжает использовать одну модель Cloud.ru, интерфейс «Мозг» не изменён.


### Дополнительный анализ памяти той же чат-моделью

Явные сообщения об устойчивых предпочтениях сначала обрабатываются существующими локальными правилами. Если правило не сработало, JUUNIBI может попросить текущую чат-модель Cloud.ru выделить не более одного долгосрочного факта из прямого утверждения пользователя и предложить его в `pending`. Старые факты при конфликте не заменяются до подтверждения. Никакой второй модели и новых кнопок не требуется. Дополнительный вызов модели возможен только для подходящих утверждений; при сбое основной ответ сохраняется.


### Защита качества автоматической памяти

Предложения модели проходят дополнительные проверки: отклоняются чувствительные данные, текст без достаточной опоры на слова сообщения пользователя, длинные или некорректные записи. Локальное извлечение также не сохраняет многострочные сообщения и очевидные секреты. Новые факты остаются неподтверждёнными до действия пользователя в существующем разделе памяти. Модель и интерфейс не меняются.
